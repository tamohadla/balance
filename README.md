# BALANCE

واجهة عربية لإدارة المخزون والطلبات، مبنية بصفحات HTML وCSS وJavaScript ES Modules، وتستخدم Supabase للمصادقة والبيانات والتخزين. تعمل على استضافة ثابتة، بما فيها GitHub Pages، دون خادم تطبيق محلي أو خطوة بناء إلزامية.

## التشغيل المحلي

يتطلب Node.js 22 أو أحدث. يُحفظ الإصدار المعتمد في `.nvmrc`.

```sh
npm ci
npm run dev
```

افتح `http://127.0.0.1:4173/`. يمكن تغيير المنفذ بواسطة متغير `PORT`. لا تفتح الصفحات باستخدام `file://`؛ وحدات JavaScript تحتاج خادم HTTP.

المعاينة المحلية تشغّل **كود التطبيق الفعلي**. الجلسة والاتصال بـSupabase يظلان فعليين ما لم تُستخدم بدائل الاختبار. استخدم حسابًا وبيئة تطوير منفصلين عند تجربة عمليات الكتابة. لا تضع مفاتيح الإدارة في الواجهة أو ملفات Git.

## التحقق قبل تسليم التعديلات

```sh
npm run check
npm test
npx playwright install chromium
npm run test:browser
```

- `check`: قواعد ESLint، وتنسيق Prettier، والتحقق من مراجع الملفات المحلية.
- `test`: اختبارات Node للنماذج والخدمات والأمان والتكامل المحلي باستخدام PGlite.
- `test:browser`: اختبارات Chromium كما يحددها إعداد Playwright. بيانات وجلسات الاختبار منفصلة عن الحسابات الحقيقية.
- `npm run format`: تطبيق التنسيق؛ راجع التغييرات قبل تثبيتها.

مسار GitHub Actions يشغّل فحوص الجودة والاختبارات عند طلبات المراجعة. لا يطبّق migrations أو يكتب في قاعدة الإنتاج.

## خريطة المشروع

| المسار                        | المسؤولية                                                |
| ----------------------------- | -------------------------------------------------------- |
| `*.html`                      | نقاط دخول الصفحات وهيكلها الثابت                         |
| `js/core/`                    | أدوات مستقلة للنصوص والأرقام وجلب صفحات النتائج          |
| `js/items/`                   | نموذج المواد وخدمتها وعرضها ومحررها                      |
| `js/inventory/`               | أدوات عرض المخزون والفلاتر والتصدير والنوافذ             |
| `js/orders/`, `js/preorders/` | خدمات الطلبات وأجزاء العرض والتحرير                      |
| `js/ui/`                      | أدوات واجهة مشتركة، مثل تحميل المكتبات وتصدير الصور      |
| `js/import-review/`           | قراءة الملفات والتطبيع والمطابقة وخدمات مراجعة الاستيراد |
| `js/*-model.js`               | نماذج نقية مشتركة أبقيت مساراتها للتوافق                 |
| `css/`                        | الأساس والتخطيط والمكونات وتنسيق الصفحات                 |
| `vendor/`                     | مكتبات واجهة مثبّتة الإصدار مع ترخيصها                   |
| `tests/`                      | اختبارات آلية دون استخدام بيانات العمل الحقيقية          |
| `supabase/`                   | مصدر Edge Functions وmigrations التاريخية                |

راجع [تفاصيل البنية وحدود الوحدات](docs/architecture.md) قبل إضافة خدمة أو صفحة جديدة.

## النشر والاعتماديات

الملفات قابلة للنشر مباشرةً تحت مسار المشروع على GitHub Pages. استخدم روابط نسبية داخل الموقع، وحافظ على أسماء صفحات HTML العامة لتجنب كسر الروابط المحفوظة. لا ترفع `.env` أو `node_modules` أو تقارير الاختبارات.

مكتبة SheetJS موجودة محليًا في `vendor/` لإبقاء الإصدار موحدًا؛ احتفظ بملف الترخيص عند تحديثها. راجع المكتبات المحملة في المتصفح أيضًا؛ `npm audit` لا يغطي اعتماديات CDN أو الملفات الموردة تلقائيًا.

ملفات `supabase/migrations/` تغييرات تراكمية فوق مخطط موجود، **وليست baseline مضمونة لإعادة إنشاء المشروع من قاعدة فارغة**. إعداد بيئة قاعدة بيانات جديدة أو تغيير المخطط مهمة مستقلة يجب أن تتضمن baseline موثقة واختبارًا محليًا. لا تُشغّل ملفات SQL الاختبارية أو migrations على الإنتاج لمجرد التحقق من تعديل واجهة.
