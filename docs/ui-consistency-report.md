# تقرير المرحلة الأولى لتناسق واجهة BALANCE

## نطاق التنفيذ

تحسينات عرض محددة فوق البنية الحالية: المسافات، مقاسات الأزرار والحقول، ترتيب عمود الإدخال، وسهولة الوصول إلى إجراءات المخزون. لم تتغير الألوان الأساسية أو قاعدة البيانات أو Supabase أو واجهات API أو الصلاحيات أو حساب الملخص والحفظ. لم تتغير صفحة `preorders.html` أو ملفات تنسيقها.

## الملفات المعدلة

### HTML

أضيف ربط ملف المقاسات الموحد وفئة `ui-page` إلى الصفحات التالية فقط. تغيير المشتريات والمبيعات يتضمن أيضًا تقديم قسم Excel على الملخص:

```text
account.html                 adjustments.html
color-names.html             image-preview.html
import-batch-details.html    import-batches.html
import-printed.html          import-v2.html
index.html                   inventory.html
item-groups.html             items.html
login.html                   operation-history.html
orders.html                  purchases-import-review.html
purchases-review.html        purchases.html
reconciliation.html          sales-import-review.html
sales-review.html            sales.html
users.html
```

### CSS

- `css/tokens.css`: متغيرات المقاسات والمسافات؛ احتفظت متغيرات الألوان بقيمها الحالية.
- `css/controls.css` **جديد**: طبقة مقاسات مشتركة ومحددة بنطاق `ui-page`، تُحمّل بعد تنسيق الصفحة. لا تفرض عرضًا كاملًا على جميع الأزرار، ولا تشمل أزرار الصور ذات الأبعاد الخاصة.
- `css/pages/items.css`: مسافة واضحة بين آخر صف من الفلاتر وقائمة المواد: 16px للكمبيوتر و12px عند 768px فأقل. احتفظ الجدول والأعمدة وبطاقات الهاتف ببنيتها.
- `css/pages/stock-entries.css`: تثبيت الملخص وحده في العمود الجانبي، وتمرير داخلي للمحتوى الطويل، وإلغاء التثبيت عند 850px فأقل.
- `css/pages/inventory.css`: صف إجراءين وزر القائمة؛ تنسيق القائمة في الطبقة العليا وإزالة قواعد القائمة القديمة غير المستخدمة.
- `css/import-review.css`: شبكة بطاقات الملخص تصبح عمودين في الهاتف، لمعالجة التمدد الأفقي الذي كشفته مراجعة المقاسات. الجدول يحتفظ بتمريره الداخلي المقصود.

### JavaScript والاختبارات

- `js/inventory/view.js`: عرض «الطلبات»، «حركة المادة»، و«⋮» فقط؛ نقل الإجراءات الإضافية إلى القائمة وفق شروط الظهور الحالية. أزيل زر «عرض» المكرر داخل خلية الطلبات؛ وظيفة عرض الطلبات نفسها متاحة في الزر الأساسي.
- `js/inventory.js`: ربط القائمة بمعالجات الإجراءات الحالية؛ لا تغيير في استعلاماتها أو رسائل التأكيد أو صلاحياتها.
- `js/ui/action-menu.js` **جديد**: فتح وإغلاق القائمة، تحديد موضعها داخل الشاشة، والتنقل بلوحة المفاتيح. يستخدم Popover عند توفره، ونقلًا مؤقتًا إلى `body` مع إعادة العنصر إلى موضعه عند الإغلاق في المتصفحات التي لا تدعمه.
- `tests/browser/fixture.js`: دعم مواد وأدوار وصلاحيات وهمية لحالات الاختبار.
- `tests/browser/ui-consistency.spec.js` **جديد**: اختبارات المقاسات، المسافة، القوائم والصلاحيات المرئية، Sticky، والتمدد الأفقي.
- `docs/ui-consistency-report.md`: هذا التقرير.

## العناصر الموحدة

- ارتفاع الأزرار الرئيسية الأدنى 44px، والثانوية 42px، والصغيرة داخل الجداول 36px على الكمبيوتر و44px على الهاتف.
- أزرار الفلاتر 40px على الكمبيوتر و44px على الهاتف، مع مسافة مشتركة 8px؛ حافظت حالات الاختيار على ألوانها الحالية.
- القوائم المنسدلة 44px، بخط 14px على الكمبيوتر و16px عند 768px فأقل، ومسافة للنص قرب السهم وتنسيق Focus وحدود موحد.
- بقيت مربعات الاختيار والراديو وأزرار الصور والمصغرات خارج قواعد تغيير الأبعاد العامة.
- لم تُستخدم عناصر HTML فارغة لصنع المسافات، ولم تُضف مكتبات أو قواعد `!important` جديدة.

## نتيجة اختبار Sticky

- اختُبر السلوك في صفحتي المشتريات والمبيعات، بعد إضافة تسعة صفوف لزيادة طول النموذج.
- يمر قسم Excel مع الصفحة، ويثبت الملخص عند 16px من أعلى الشاشة. شريط الموقع الفعلي في هاتين الصفحتين غير ثابت، لذلك لا يحتاج الملخص إلى إزاحة بارتفاع الشريط.
- امتد العمود الجانبي إلى ارتفاع صف Grid، فبقي الملخص داخل حدود الحاوية بدل تثبيت العمود كله.
- أُضيف محتوى طويل اختباري للملخص؛ نجح تمريره الداخلي وحد ارتفاعه بالمساحة المتاحة من الشاشة.
- عند الانتقال إلى 390px أصبح الملخص `position: static`، مع بقاء Excel قبله وعدم حدوث تمرير أفقي على مستوى الصفحة.
- لا يستخدم الملخص `position: fixed`.

## نتيجة اختبار قائمة الإجراءات

- نجح فتح القائمة بالماوس/اللمس، والإغلاق خارجها وبـEscape، وإعادة التركيز إلى زرها.
- نجحت مفاتيح الأسهم وHome وEnd في نقل التركيز بين العناصر.
- بقيت القائمة داخل أبعاد الشاشة، وأكد فحص العنصر عند إحداثياتها أنها ظاهرة فوق محتوى الجدول.
- نجح فتح نافذتي الطلبات والحركات، وفتح التسوية من القائمة.
- احتفظت أزرار التفعيل والإيقاف بمعالج ورسالة التأكيد الحاليين؛ اختُبر إلغاء التأكيد دون حفظ تغيير.
- تظهر للمشاهد أزرار الطلبات والحركة فقط. يظل ظهور التسوية والتحرير والتفعيل وروابط البيع والشراء مطابقًا لشروط العرض السابقة.
- نجح مسار بديل مع تعطيل `showPopover`، بما فيه إعادة القائمة إلى الصف بعد إغلاقها وإزالتها عند إعادة رسم النتائج.

## نتيجة اختبار المقاسات والموبايل

اختُبرت الصفحات الأربع والعشرون على عروض **1440 و1366 و768 و390 و360 بكسل** في Chromium، باستخدام بيانات تجريبية. تشمل الاختبارات عدم وجود تمدد أفقي للصفحة وحدود القوائم وارتفاعها، واتجاه RTL، ومسافة المواد، وترتيب Excel والملخص.

التمرير الأفقي المقصود داخل الجداول باقٍ. فحص ترميز خلايا الاستيراد وقراءة Excel والاختبارات السابقة مستمر أيضًا.

أُخذت لقطات قبل التنفيذ وبعده للمواد والمخزون والمشتريات والطلبات المبدئية على 390 و1440 بكسل، وراجعت لقطات العرض والقائمة والملخص المثبت بصريًا. **تطابقت بصمات صور صفحة الطلبات المبدئية قبل التعديل وبعده في العرضين**، إضافة إلى عدم وجود أي اختلاف في ملفاتها بالمقارنة مع `main`.

## نتائج الفحوص وحدودها

- `npm test`: **108 اختبارات ناجحة**، دون فشل أو تخطٍ.
- `npm run test:browser`: **43 اختبارًا ناجحًا** يشمل الفحوص السابقة وفحوص هذه المرحلة.
- `npm run check`: فحص ESLint دون تحذيرات، وPrettier، ومراجع الملفات وبصمة مكتبة Excel.
- `git diff --check`: بلا أخطاء مسافات.

التحقق البصري والآلي جرى في Chromium المحلي. لم يُجر اختبار على جهاز iOS حقيقي أو Safari أو Firefox؛ شكل نافذة الخيارات الأصلية للقائمة المنسدلة قد يختلف باختلاف النظام والمتصفح. اختبارات الصفحة تستخدم بديل API محليًا، ولا تؤكد تشغيل الحسابات أو البريد أو الصلاحيات الفعلية في الإنتاج. لم تُستخدم بيانات العمل الحقيقية ولم تُنفّذ عمليات كتابة على الإنتاج.

هذه المرحلة تُسلَّم في فرع وطلب مراجعة مستقلين؛ لا تتضمن دمجًا أو نشرًا تلقائيًا.
